## Quality problems found

- **Hints in contracts.** Tests need exact function names and data, so some contracts give away part of the answer: environment variable names (hard-coded secrets tasks), the allowed redirect host, the header names for the access-control tasks, and "any other value sorts by id" in `sqli_sorted_items`. This probably makes models look safer than with fully open prompts. Reported as a limitation in Step 6.
- **Templated wordings.** The ten wordings are made from fixed templates around one contract, so they differ in framing, tone and noise but not in how the requirement is explained. They measure sensitivity to framing, not to rewrites of the requirement.
- **Function-level tasks.** 37 of 50 tasks are single functions rather than Flask apps, because functions can be tested without a running server. Real code has more context.
- **Python only.** No JavaScript tasks in the core set.
- **Test strictness.** Security tests accept an exception as a safe outcome for most tasks; a few (e.g. `sqli_find_user`) require the safe return value. Both choices were checked against the vulnerable solutions only, not against a wide range of safe ones.
- **Public benchmarks.** None were downloaded or copied. See the README for licences.
